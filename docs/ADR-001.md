# ADR 001 — Fondation locale, indépendante des moteurs pédagogiques

Décision du 12 octobre 2026. Dépôt initial : CODEX_BRIEF.md et un README minimal (commit e9afe03), aucun code à conserver ou migrer.

Next.js App Router / React / TypeScript, FastAPI et SQLAlchemy. PostgreSQL 17 dans Compose ; SQLite pour développer sans Docker. API même origine via le proxy Next ; aucun appel fournisseur IA. CSS à tokens et composants accessibles natifs : Tailwind/shadcn différés, sans imposer un kit avant de stabiliser le design. Pas de microservices, stockage de fichiers, pgvector, jobs ni paiements inutilisés au Sprint 1.

Sessions opaques aléatoires, empreintes SHA-256 en base, expiration 8 h et révocation au logout. Mots de passe Argon2 via pwdlib. Cookie HttpOnly/SameSite=strict, Secure configurable pour HTTPS ; contrôle d'origine strict sur mutations. Ce mécanisme de démonstration local est remplaçable par OIDC/MFA avant pilote. Aucun mot de passe de production, inscription ou récupération de compte. Le mode autre que local/test est refusé pour empêcher de servir accidentellement les comptes publics de démo.

Chaque requête personnelle est filtrée par membership et utilisateur. Les parents consultent uniquement les agrégats de leurs enfants explicitement liés ; pas les données des autres adultes. Changer de compte impose une authentification ; le sélecteur public ne donne accès qu'aux fixtures en mode local. Les tests attaquent directement les endpoints, sans s'appuyer sur l'interface. RLS PostgreSQL différée : rôle SQL technique unique et filtrage applicatif vérifié au Sprint 1 ; défense supplémentaire obligatoire avant ouverture externe.

Pas de fork complet : les produits audités ne fournissent pas la séparation familles/générations requise. Aucune copie de leur code. Voir OSS_AUDIT.md. ts-fsrs sera réévalué au Sprint 2 derrière un adaptateur ; rien n'est installé aujourd'hui.

Sources consultées : [PWA Next](https://nextjs.org/docs/app/guides/progressive-web-apps), [sécurité FastAPI/pwdlib](https://fastapi.tiangolo.com/tutorial/security/oauth2-jwt/). Ces guides éclairent la mise en œuvre, pas une certification sécurité.

Ordre : schéma/migrations et contrôle d'accès → contrat API → expérience responsive → tests API/E2E/build → PR. Aucun hébergement ni ressource cloud.
